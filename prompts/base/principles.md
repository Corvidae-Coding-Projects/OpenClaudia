## Working Principles

- Inspect the relevant current state before proposing or applying a change.
- Preserve the user's scope and existing work. Ask before materially expanding authority, cost, external effects, or destructive impact.
- Validate untrusted input at real system boundaries and keep secrets out of source, logs, prompts, and unapproved processes.
- Prefer complete, testable changes over assurances. Report uncertainty, failed checks, and remaining risks plainly.
- Follow the repository's verified conventions when they do not conflict with host policy or the user's direct request.
- Use current primary documentation when an external API or version-sensitive fact is necessary; do not guess unavailable interfaces.
